# Glide wire protocol, version 1

Source of truth: `packages/glide_protocol`. Every message is a JSON object in a
WebSocket text frame. Unversioned messages are never accepted.

## Envelope

```json
{
  "protocol": 1,
  "id": "3f0c6c0e-...-uuid-v4",
  "type": "session.status",
  "timestamp": 1789965000000,
  "payload": {}
}
```

- `protocol` must equal `1`, otherwise the message is rejected.
- `id` is a non-empty string of at most 64 characters.
- `type` is a non-empty string of at most 64 characters.
- `timestamp` is milliseconds since the Unix epoch.
- `payload` is a JSON object (defaults to `{}`).
- A single encoded message may not exceed 256 KiB.

## Message types

| Group | Types |
|---|---|
| Session | `session.created`, `session.connected`, `session.disconnected`, `session.status`, `session.snapshot` |
| Pairing | `pairing.request`, `pairing.accepted`, `pairing.rejected`, `auth.resume` |
| Devices / project | `device.discovered`, `device.ready`, `device.error`, `project.detected`, `project.updated` |
| Build / app | `build.started`, `build.progress`, `build.completed`, `build.failed`, `app.starting`, `app.started`, `app.stopped` |
| Reload / restart | `reload.started`, `reload.completed`, `reload.failed`, `restart.started`, `restart.completed`, `restart.failed`, `restart.required` |
| Observability | `log.entry`, `logs.cleared`, `error.reported`, `performance.sample`, `network.request`, `network.response` |
| Feedback | `command.rejected` |

## `restart.required`

Sent by the host while an app is starting or running, when project files
changed that hot reload cannot apply (native code, Gradle or Xcode
configuration, `pubspec.yaml`, `pubspec.lock`). It is sent again only when a
new file is added to the pending set.

```json
{
  "count": 2,
  "reasons": [
    {
      "path": "android/app/build.gradle",
      "impact": "fullRestart",
      "reason": "Android build configuration changed",
      "platform": "android"
    }
  ]
}
```

- `path` is relative to the project root, with forward slashes; it never
  contains an absolute path.
- `reasons` holds at most 20 entries; `count` is the real total.
- `platform` is omitted for changes that apply to every platform.
- The pending set is cleared by a full restart, stop, exit or failed build.
  `session.snapshot` includes `count` and `reasons` while the set is not
  empty and omits them otherwise.
- Hot reload is not blocked while changes are pending.

## Commands the companion may send (the entire allowlist)

| Command | Payload |
|---|---|
| `app.run` | optional `deviceId` |
| `app.stop` | none |
| `app.reload` | none |
| `app.restart` | optional `mode`: `hot` (default) or `full` |
| `logs.clear` | none |
| `session.disconnect` | none |
| `diagnostics.request` | none |

Anything else is rejected with a `ProtocolException`. `deviceId` must match
`^[A-Za-z0-9._:@\-]{1,128}$` so it can never carry shell syntax.

## Pairing URI (QR payload)

```text
glide://pair?version=1&host=192.168.1.20&port=49400&session=GLIDE-7X21-K94&token=<256-bit url-safe token>&exp=<epoch ms>
```

The parser rejects other schemes, other versions, invalid hosts, ports outside
1-65535, malformed session ids or tokens, and codes without an expiry.

## Pairing handshake

The companion holds only the one-time QR token, so pairing happens on a
separate, unauthenticated WebSocket path. Everything else requires a session
token.

1. Companion connects to `ws://<host>:<port>/pair`.
2. Companion sends exactly one frame (at most 4096 characters):

   ```json
   {
     "protocol": 1, "id": "...", "type": "pairing.request", "timestamp": 0,
     "payload": {
       "session": "GLIDE-7X21-K94",
       "token": "<token from the QR code>",
       "deviceId": "phone-1",
       "deviceName": "Pixel 10"
     }
   }
   ```

3. The host validates the token (single use, 5 minute expiry, five wrong
   attempts revoke the pairing), asks the developer to approve the device, and
   replies with one frame before closing:

   - `pairing.accepted`, payload `sessionId`, `sessionToken`, `deviceId`,
     `protocol`.
   - `pairing.rejected`, payload `code` and `reason`. Codes:
     `noActivePairing`, `invalidToken`, `expired`, `alreadyUsed`, `revoked`,
     `tooManyAttempts`, `rejectedByHost`, `malformed`, `timeout`, `internal`.
     The reason never contains the token.

4. The pairing token is now spent. The companion sends `sessionToken` in the
   `x-glide-control-token` header on `GET /ws`, `GET /v1/session` and
   `GET /v1/project`.

`deviceName` is untrusted: the host strips control and bidirectional-override
characters and caps it at 64 characters before displaying it. `/pair` closes if
no request arrives within 10 seconds.

## HTTP routes

| Route | Auth | Purpose |
|---|---|---|
| `GET /health` | none | liveness, protocol version |
| `GET /pair` (WebSocket) | none (QR token in the request) | pairing handshake above |
| `GET /v1/session` | session token | session id, state, project name |
| `GET /v1/project` | session token | project details (no absolute path) |
| `GET /ws` (WebSocket) | session token | command and event channel |

## Session states

`disconnected`, `pairing`, `connected`, `preparing`, `building`, `installing`,
`launching`, `running`, `reloading`, `restarting`, `stopping`, `failed`.
Transitions are validated by `SessionStateMachine`; any state may move to
`failed`.
